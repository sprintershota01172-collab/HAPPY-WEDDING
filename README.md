# Happy Wedding ✿

**ふたりで楽しく進める、スマホ向け結婚式準備アプリ。**

挙式日は**初回セットアップで各カップルが登録**します。共通の固定日付はありません。登録後も設定から変更できます。

## アプリを開く

GitHub Pages を有効化すると以下で開けます。

**https://sprintershota01172-collab.github.io/HAPPY-WEDDING/**

初回は **挙式日（必須・初期値なし） → 自分の役割** の2ステップです。iPhoneのSafariから「共有」→「ホーム画面に追加」でアプリ風に使えます。

> GitHub Pages が未設定のリポジトリでは、上記URLは有効ではありません。リポジトリの Settings → Pages → Build and deployment → Source で **GitHub Actions** を選択してください。Actionsでデプロイが成功すると公開されます。

## 画面

| 画面 | 機能 |
|---|---|
| ホーム | 挙式までの日数、全体進捗、支払い、ひとことコメント |
| やること | 自分・役割別タスク、進捗、サブタスク、写真・URL、半年前〜式後テンプレ、個別サブタスク完了 |
| お金 | 全体と項目別予算、見積・契約・支払済・残額、支払期限カレンダー、ご祝儀、予算バー |
| ゲスト | 出欠、住所、親族・友人・職場、アレルギー、引出物・車代・宿泊、招待状送付、席次表 |
| その他 | 当日進行、業者・打ち合わせ、アイデア、持ち物、お礼、役割、共有、JSON/CSV、設定 |

ローカル環境で `index.html` を直接開くとService Workerや一部機能は動作しません。PagesなどのHTTPSホスト、またはlocalhostで実行してください。


## 操作デザイン（v2）

- iPhone向けの上質なアイボリー・セージグリーン・ダスティローズ基調
- 画面全体の縦スクロールはなし。ヘッダー・サマリー・下部ナビゲーションは固定し、一覧・詳細のみ専用枠内をスクロール
- タスク・ゲスト・予算はナビゲーションからワンタップ。タスクを完了しても一覧のスクロール位置を保持
- 初回は挙式日の選択が必須。特定のふたり専用アプリではなく、どのカップルも利用可能
- 端末内にすでに保存された挙式日・各種データは、新しいバージョンで引き続き利用


## コンパクトUI（v3）

- ゲストの追加・編集は「基本／出欠・配慮／費用・メモ」を切り替える3ステップ方式。**ダイアログ全体をスクロールせず**に登録できます。iPhoneの極小画面・キーボード表示中だけ、入力セクション内部にスクロールを許可します。
- ゲスト一覧、タスク帯、金額・支払・進行・席次のカードを狭い画面向けに統一してコンパクト化。タッチ対象は操作に必要な大きさを保ちます。

## パートナーの変更通知

**通知には「アプリを開いているとき」と「閉じているとき」の二段階があります。**

### 1. リアルタイム変更通知（共有設定後に利用可能）

上記のFirebase接続と、更新した `firestore.rules` の反映が必要です。

- 変更を行うと `activity` レコードがFirestoreに追加され、パートナー側が接続している間は画面上部のベルとトーストでお知らせします。
- 追加・編集・完了・削除の操作に対応。通知には操作した役割と変更セクションが表示されます。
- 同じ端末からの更新や初回同期の既存データを新着として表示しません。
- 画面を閉じていた間の変更も、再接続時にベルの未読履歴として確認できます。
- 通知履歴は最新100件を端末内に記録します。履歴は端末別で、通知を開くと既読になります。

### 2. アプリを閉じている間のWebプッシュ通知（任意・追加設定が必要）

このリポジトリには**Cloud Functions用の配信コードを用意しましたが、Firebaseプロジェクトへの配備は自動ではありません**。設定・デプロイが完了するまでバックグラウンド配信は動きません。

1. FirebaseのCloud Functionsが使える料金プラン・課金設定を確認します（通常Blazeプランが必要です）。
2. Node.js と Firebase CLI を用意し、`firebase login`、`firebase use <PROJECT_ID>` を実行します。
3. `npx web-push generate-vapid-keys` などで **VAPID公開鍵・秘密鍵** を作成。秘密鍵をGitHubにコミットしないでください。
4. `functions/.env.example` を参考に `functions/.env` に `VAPID_PUBLIC_KEY` と自分の管理メールアドレスを `VAPID_SUBJECT=mailto:...` で設定します。`functions/.env` はgitignore済みです。
5. `firebase functions:secrets:set VAPID_PRIVATE_KEY` で**秘密鍵**を設定します。
6. `cd functions && npm install && cd ..` を実行し、`firebase deploy --only firestore:rules,functions` でデプロイします。
7. アプリの「その他 → ふたりで共有」で**VAPID公開鍵**を入力して保存します。接続した**各端末**で「その他 → 基本設定 → パートナー通知を許可」を押してください。
8. iPhoneの場合はSafariで開いたページを**ホーム画面に追加**し、そのPWAから通知を許可してください。ブラウザ・OSの通知設定でも許可が必要です。

**仕様・注意点**：Webプッシュの通知文にはゲスト名・金額などの個人情報を載せず、汎用的な「パートナーが結婚式準備を更新しました」のみを表示します。通信環境、OSの省電力制限、通知権限、Firebaseの設定によっては即時に届かないことがあります。

## ローカル保存とオフライン

- 入力したデータは端末の `localStorage` に自動保存
- Service Workerがアプリ画面のファイルをキャッシュしてオフラインでも開けるようにする
- JSONバックアップ、JSON復元、項目別CSV書き出し対応
- 写真は小さくリサイズして保存（画像が増えた場合は保存容量制限があります）
- ブラウザのプライベートモード、サイトデータ削除、iOSの保存領域の違いで消失する可能性があるため、定期的にバックアップを取ってください

## ふたりの端末間でリアルタイム同期するには

**Firebase設定が必要です。** Firebaseの認証やデータベースをこちらで自動作成するものではありません。設定を済ませるまで端末間の同期はありません。

1. [Firebase Console](https://console.firebase.google.com/) でプロジェクトを作成
2. Authentication → Sign-in method で **Anonymous** を有効化
3. Cloud Firestore データベースを作成し、このリポジトリの `firestore.rules` をFirestoreルールに貼り付けて公開
4. プロジェクトにWebアプリを追加し、Firebaseの設定値から `apiKey`・`projectId`・`appId`・`authDomain` を控える
5. アプリの「その他 → ふたりで共有」に入力して、「新しい共有コードを発行」→「保存して接続」
6. もう一方の端末にも同じFirebase設定と**同じ共有コード**を入力し、保存・接続

共有コードは暗号学的乱数で生成した48文字の招待キーです。**コードを知る人はそのルームのデータを読み書きできる**仕組みです。コードを他人に公開せず、機密データを扱う場合は、より強固なユーザー別アクセス制御が必要です。Firebaseプロジェクトの利用状況・費用・ルールは所有者側で管理してください。

同期はドキュメント単位の上書き方式です。**同じ項目を二人が同時編集した場合、最後にクラウドへ保存された内容が優先**されます。通信切断中は端末に保存し、クラウド設定済みであれば変更を後で送信します。端末を変えるときや共有を切り替えるときはデータのバックアップを取ってください。大容量写真の同期にはFirestoreのドキュメント制限があるため、大きな画像を直接保存しないよう制限しています。

## 通知

期限が3日以内または超過したタスク・支払予定をアプリ起動・復帰時に知らせます。パートナーの変更はFirebase共有接続中にリアルタイム通知されます。閉じている間のWebプッシュは上記の追加設定・デプロイが完了した場合のみ利用できます。

## 仕様補足

- 項目ごとの「支払済み」は、登録した支払予定のうち完了済み金額と「予定にない支払済額」の合計です。同じ費用を両方に入れると二重計上します。
- 最終持ち出し見込み = max(0, 契約額または見積の合計 − ご祝儀・支援金の登録額)
- ゲスト詳細で入力したご祝儀も収入に加算されます。ご祝儀リストに重複登録しないよう注意してください。
- 未契約の項目は見積額、契約済みの項目は契約額を優先します。実際の請求総額を保証するものではありません。
- 席次表はタップ操作とドラッグ＆ドロップに対応します。
- 役割は誰でも追加・編集でき、初期値は新郎／新婦／両家の親／受付係／司会・友人幹事／プランナーです。
